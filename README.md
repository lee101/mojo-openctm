# mojo-openctm

`mojo-openctm` is a standalone OpenCTM v5 reader and writer with the
compute-heavy MG1 and MG2 transforms ported to Mojo. It reads and writes real
`.ctm` files, preserves lossless MG1 floating-point data, and implements MG2
grid quantization plus index, vertex, normal, UV, and attribute prediction.

This is an altered derived work of
[OpenCTM 1.0.3](https://github.com/Danny02/OpenCTM), originally by Marcus
Geelnard and released under the zlib/libpng licence. The ported source remains
under that licence; its complete notice is in [NOTICE](NOTICE). Repository
glue and original code are covered by [LICENSE](LICENSE).

## Coverage

Implemented:

- OpenCTM v5 container parsing and serialization
- MG1 triangle rearrangement and index prediction
- MG1 bit-exact float streams for vertices, normals, UV maps, and attributes
- MG2 spatial grids, vertex sorting, fixed-point quantization, and X prediction
- MG2 smooth-normal prediction and angular normal coding
- MG2 delta-coded UV and four-channel attribute maps
- OpenCTM's byte-plane integer/float layout, signed mapping, and marker-less
  LZMA stream decoding
- file comments, multiple named maps, in-memory and file APIs

Not implemented:

- the uncompressed `RAW` method
- OpenCTM's C context, property-query, custom stream callback, and relative
  vertex-precision APIs
- a Mojo port of the LZMA entropy coder itself; the byte-plane preparation is
  Mojo, while compression uses Python's standard `lzma` module and emits a
  standard LZMA1 raw stream accepted by upstream OpenCTM
- OpenCTM conversion/viewer tools and non-CTM mesh formats

OpenCTM rejects empty meshes, and this port matches that behavior. Duplicate
vertices, zero-area faces, non-manifold edges, and unreferenced vertices are
accepted and preserved.

## Install

```bash
pixi install
pixi run build
pixi run test
```

The package is available from the repository through the `PYTHONPATH` set in
`pixi.toml`. Public inputs must use `float32` mesh data and integer triangle
indices. Wider floating NumPy arrays are rejected instead of silently narrowed;
convert them explicitly when the loss of precision is intended.

## Usage

```python
import numpy as np
import mojo_openctm as ctm

vertices = np.array(
    [[0, 0, 0], [1, 0, 0], [0, 1, 0]],
    dtype=np.float32,
)
triangles = np.array([[0, 1, 2]], dtype=np.uint32)
uv = np.array([[0, 0], [1, 0], [0, 1]], dtype=np.float32)

encoded = ctm.dumps(
    vertices,
    triangles,
    uv_maps={"uv0": uv},
    method="MG2",
    vertex_precision=1 / 1024,
)
mesh = ctm.loads(encoded)

ctm.save("triangle.ctm", vertices, triangles, method="MG1")
same_mesh = ctm.load("triangle.ctm")
```

MG2 reorders vertices and triangles for compression, as upstream OpenCTM does.
Consumers should treat decoded indices and vertices as a new but equivalent
index space.

## Correctness

No maintained installable Python binding for this exact OpenCTM C library was
available. Parity therefore uses two stronger source-level references:

- fixed MG1 and MG2 streams generated by unmodified OpenCTM 1.0.3, checked
  exactly for vertices, indices, normals, UV maps, attributes, names, and
  quantization results
- direct NumPy references transcribed from upstream `compressMG1.c`,
  `compressMG2.c`, and `stream.c`

Files written by this project were also loaded successfully by an unmodified
build of upstream OpenCTM. Tests include empty input, a single triangle,
duplicate vertices, zero-area faces, non-manifold edges, unreferenced vertices,
invalid indices, non-finite coordinates, damaged sections, and truncated LZMA
data.

## Benchmarks

Run with `pixi run bench`; the task takes a machine-wide lock. This is the
complete output table from a run on this machine (`Intel(R) Xeon(R) CPU
E5-2697 v4 @ 2.30GHz; Linux x86_64`):

| Kernel | Mojo | NumPy reference | Speedup |
|---|---:|---:|---:|
| MG1/MG2 index prediction, 1M tris | 2.10 ms | 10.75 ms | 5.12x |
| LZMA integer interleave, 6M ints | 6.17 ms | 28.92 ms | 4.69x |
| MG2 smooth-normal prediction, 798K tris | 13.05 ms | 979.81 ms | 75.08x |

The NumPy columns run source-equivalent reference algorithms on the same input.
The benchmark checks output parity before printing results.

Thresholded CPU parallelism was tested for the two streaming transforms but
regressed their locked benchmark times, so the optimized kernels remain serial.
Their contiguous SIMD loads already approach the memory-bandwidth limit without
thread-launch overhead.

GPU acceleration is intentionally omitted. The profiled optimization targets
are streaming transforms with fewer than two arithmetic operations per byte
moved, while smooth-normal prediction is already far ahead on the CPU. Device
transfer and launch overhead would make these kernels slower, not faster.

## How it works

Python owns contiguous NumPy buffers and passes their addresses as 64-bit
integers through a small `ctypes` C ABI. Exported Mojo functions reconstruct
`UnsafePointer` values with `AnyOrigin[mut=True]`; no Mojo allocation crosses
the ABI.

Hot mesh data stays in flat row-major `float32`, `int32`, or `uint32` arrays.
Packed CTM streams use four byte planes in most-significant-byte-first order,
exactly as OpenCTM's `stream.c` does before LZMA. Python handles section framing,
strings, sorting orchestration, and LZMA1; Mojo handles the linear scans,
prediction, quantization, coordinate bases, and accumulation kernels.
